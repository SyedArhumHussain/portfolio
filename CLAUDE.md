# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Single-page personal portfolio in plain PHP 8+ (no framework, no Composer, no build step, no tests). Vanilla JS and one CSS file; fonts come from Google Fonts.

## Running

```
php -S localhost:8000      # from the repo root, then open http://localhost:8000
php -l <file>.php          # syntax-check a file after editing
```

Alternatively the folder can be dropped into XAMPP `htdocs/` (then http://localhost/portfolio/).

## Deployment

Hosted on Hostinger (arhumhussain.site) via its "Deploy from GitHub" integration: the `main` branch of `github.com/SyedArhumHussain/portfolio` is deployed into `public_html`, so **pushing or merging to `main` publishes to the live site**. Deployment is a plain git pull — no build step, no Composer/npm install, no env vars, no DB migrations — so everything the site needs must be committed as-is. Server-only files (secrets etc.) belong in gitignored names (`*.local.php`, `.env`) created directly on the server; don't edit tracked files on the server or the next pull may conflict.

## Architecture

- **`config/config.php` is the single source of content.** It calls `session_start()` and defines the data arrays `$site`, `$mail`, `$projects`, `$skills`, `$experience`, `$education`, plus shared helpers: `e()` (HTML escaping; use it for all output), `icon()`, `socials()`, `arrow()`. To change text, projects, skills, etc., edit these arrays rather than the templates.
- **`index.php`** requires the config and includes `includes/*.php` partials in a fixed order (header, navigation, then hero/about/projects/skills/experience/education/contact inside `<main>`, then footer). Partials are plain templates that read the global arrays. The `contact` nav entry gets special `talk` styling and an arrow in `navigation.php`. Adding a section means adding a partial, adding it to the list in `index.php`, and adding a nav entry to `$site['nav']` (keys are section ids; `script.js` scroll-spy matches `data-spy` attributes against `main > section` ids). Section headings and the numbered eyebrow labels (`01 / ABOUT` … `06 / CONTACT`) are hardcoded in each partial, not in the config, so inserting or reordering a section means renumbering those labels by hand.
- **Contact flow:** `includes/contact.php` renders the form, creates the CSRF token in `$_SESSION['csrf']`, and displays `$_SESSION['flash']` / `$_SESSION['old']` (one-shot, unset after reading). `process_contact.php` checks CSRF, a honeypot field (`website`, silently "succeeds" for bots), validates/sanitises fields, sends with `mail()`, then redirects back to `index.php#contact` via `back()` (Post/Redirect/Get). Validation rules live server-side; JS only calls `reportValidity()` as a hint. Keep the flash (`ok`/`msg`/`errors`) and old-input keys in sync between the two files. The CSRF token is only rotated after a successful send. Recipient/from/subject prefix come from `$mail` in the config. The `maxlength` limits (150 / 5000) exist only in the HTML; the server checks only minimum lengths.
- **Project illustrations** are inline SVGs generated by `art()` in `includes/projects.php`, keyed by each project's `art` value (`amd`, `care`, anything else falls back to the RAG chart).
- **`assets/js/script.js`**: one IIFE handling the mobile menu, scroll-spy, skills accordion (`.acc`), fade-in of `.card`/`.item`, back-to-top (`#totop`), and form validation hint.

## Conventions / gotchas

- Profile photo: `assets/images/profile.jpg` is auto-detected; otherwise the placeholder SVG is used.
- Project cards render "View Project" and "GitHub" buttons from each project's `view`/`github` URLs (an empty one shows a disabled "link pending" span); the card title links to `view`, falling back to `github`. Don't invent URLs.
- `mail()` requires a configured MTA/SMTP in php.ini. When it fails, the form shows an honest error pointing to the site email — do not change it to fake success. The README suggests switching to PHPMailer with SMTP for production; that is not implemented.
- Code style is deliberately compact (short variable names, dense one-liners); match it.
